## 4. #110 — Feature: Wichtige Links

**Korrektur ggü. Issue-Text:** Es gibt kein `/admin/downloads` — Downloads-Verwaltung läuft inline auf `/downloads` (Public-Route mit `canManage`-Gate). Für „Wichtige Links“ ist eine **eigene Admin-Route** `/admin/wichtige-links` konsistenter mit dem übrigen Administration-Nav, da laut AC ein eigener Nav-Eintrag verlangt ist.

**Prisma (neues Modell):**
```prisma
model ImportantLink {
  id        String   @id @default(cuid())
  title     String
  targetUrl String
  iconUrl   String?
  order     Int      @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@map("important_links")
}
```
Migration: `pnpm prisma migrate dev --name add_important_link`.

**Neue Permission:** `links:manage` in `prisma/seed.ts` `PERMISSIONS`, Rolle `admin` (ggf. `moderator`).

**lib-Layer** (`src/lib/links/`):
- `links.ts`: `listImportantLinks()` (sortiert nach `order`).
- `actions.ts`: `createImportantLink`, `updateImportantLink`, `deleteImportantLink`, `reorderImportantLinks`, `getImportantLinkUploadToken` — 1:1 nach Muster `src/lib/downloads/actions.ts` (Permission-Check, `revalidatePath("/admin/wichtige-links")` + `revalidatePath("/dashboard")`, `deleteBlobs()` bei Löschung).

**Components:**
- `src/components/feature/admin-links/admin-links-view.tsx` — Tabelle analog `admin-news-view.tsx`/`downloads-view.tsx`.
- `src/components/feature/admin-links/link-form.tsx` — Create/Edit-Formular analog `download-upload-form.tsx`, Icon via `useBlobUpload("important-links", getImportantLinkUploadToken)` + `compressImage()` aus #107.
- `src/components/widgets/important-links-grid.tsx` — datengetriebenes Card-Grid für `/dashboard` (Icon, Titel, ganze Karte klickbar zu `targetUrl`), analog zum bisherigen hartcodierten `QUICK_LINKS`-Grid.

**Nav & Routen:**
- `nav-config.ts`: neuer Eintrag unter „Administration“, `href: "/admin/wichtige-links"`.
- `src/app/admin/wichtige-links/page.tsx` (neu).
- `dashboard/page.tsx`: zusätzlicher `listImportantLinks()`-Aufruf, an `DashboardView` durchreichen, neue Sektion (kein eigener Nav-Eintrag für die Dashboard-Sektion selbst).

**Tests:** `src/lib/links/links.test.ts`, `src/lib/links/actions.test.ts` (Permission-Verweigerung, CRUD, Blob-Löschung, Reorder) — 1:1 Muster von `src/lib/downloads/actions.test.ts`.

**Bei Sprintstart kurz bestätigen:** eigenes Modell vs. `Download`-Wiederverwendung (Empfehlung: eigenes Modell), Bild-Upload vs. feste Icon-Auswahl (Empfehlung: Bild-Upload), manuelle Drag&Drop-Reihenfolge nötig oder reicht Erstellungsdatum.

## 5. #135 — Vorschau/Vollansicht-Schalter + Infinite Scroll auf `/news`

**Ist-Zustand:** `/news/page.tsx` lädt aktuell `Omit<ContentItem, "body">[]` — Body wird nur einzeln auf der Detailseite geladen. `news-browser.tsx` rendert die komplette Liste ohne Pagination.

**Kernentscheidungen:**
- `body` wird beim initialen Laden von `/news` mitgeschickt (ein Request, News-Volumen ist klein) — `getAllContentWithCalendar()`/Aufrufer in `content.ts` entsprechend erweitern.
- Infinite Scroll = reines Client-seitiges Slicing der bereits gefilterten Liste (10 initial, +5), kein Server-Pagination nötig bei aktuellem Datenvolumen.
- **Slicing-Berechnung** (welche Items bei welchem Filter/Count sichtbar sind) gehört nach `src/lib/content/` — DOM-frei, testbar, Coverage-Pflicht.
- **`IntersectionObserver`-Wiring** bleibt in `src/components/ui/use-infinite-scroll.ts` (generisch: `{ items, initialCount, step } → { visibleItems, sentinelRef }`), analog zur Einordnung von `use-code-scanner.ts`.
- Reset bei Filterwechsel: `visibleCount` zurück auf initiale 10, um Verwirrung zu vermeiden.

**Datei-Aufteilung** (wegen 400-Zeilen-Grenze durch View-Toggle + Infinite-Scroll-Wiring):
- `news-browser.tsx` — Orchestrierung: Filter-State (wiederverwendet aus #134), View-Toggle-State, ruft `useInfiniteScroll`.
- `src/components/entities/content-timeline-entry.tsx` (neu) — Vollansicht-Eintrag mit vollem Markdown-Body, Cover, Metadaten.
- `src/components/ui/use-infinite-scroll.ts` (neu) — generischer Scroll-Hook.

**Dateien:** `src/app/news/page.tsx`, `src/lib/content/content.ts`, `src/components/feature/news/news-browser.tsx`, `src/components/entities/content-timeline-entry.tsx` (neu), `src/components/ui/use-infinite-scroll.ts` (neu). **Nicht** `admin-news-view.tsx` — AC schließt `/admin/news` explizit aus.

**Tests:** Slicing-Berechnung in `lib/content/` → Coverage-Pflicht. Components (`news-browser.tsx`, `content-timeline-entry.tsx`, `use-infinite-scroll.ts` in `components/ui/`) → keine Pflicht, aber freiwillig empfohlen.

**Bei Sprintstart kurz bestätigen:** Body initial mitladen (Empfehlung) vs. Lazy-Load beim View-Wechsel; Reset-Verhalten bei Filterwechsel.

**Modell:** **Opus** — einzige Stelle im Sprint mit echtem State-Design-Bedarf (Filter × View-Umschaltung × Scroll-Reset, kein Vorbild im Repo). Die übrigen 4 Issues: Sonnet.
