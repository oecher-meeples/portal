## Issue #150 — Event anlegen: Uhrzeit für Beginn/Ende kann nicht angegeben werden
Grundlage für alle Zeitraum-Rechnungen (#153, #157). Kein Label — nicht `needs-refinement`, daher ohne vorherigen `issue-refine`-Lauf direkt umgesetzt.

**Umgesetzter Scope (nach Rücksprache, weicht vom ursprünglichen Issue-Text ab):**
Der Live-Code-Abgleich zeigte, dass `type="datetime-local"` bereits vorhanden war — Nutzer-Klarstellung ergab den eigentlich gewollten Ablauf: Event wird nur mit Titel, Ort und Datumsbereich (von/bis, ohne Uhrzeit) angelegt; die Öffnungszeit je Tag wird danach auf der Event-Detailseite gepflegt.

- Neues Modell `EventDay` (1 Zeile pro Kalendertag im Event-Zeitraum, `startsAt`/`endsAt` nullable) — Migration `20260827141426_add_event_day`.
- `src/lib/events/event-days.ts`: `enumerateEventDates` (Tage aus Event-Zeitraum ableiten) + `endOfUtcDay` (verhindert, dass ein Event durch den reinen Datumsbereich für den Rest seines letzten Tages als "beendet" gilt — betrifft `isEventCurrentlyRunning`/`UPCOMING_EVENT_WHERE`/Bring&Buy-Fenster in `src/lib/events/upcoming.ts`).
- `actions.ts`: `createEvent`/`updateEvent` synchronisieren `EventDay`-Zeilen bei jedem Speichern (`syncEventDays`), `endsAt` wird als Tagesende gespeichert.
- Neue Action `event-day-actions.ts` (`updateEventDayTimes`) + Komponente `event-day-time-form.tsx` für die Zeitpflege je Tag auf der Event-Detailseite.
- `EventDialog`: Felder auf `type="date"` umgestellt (kein `datetime-local` mehr).
- `formatDateRange` (neu, `lib/utils/format.ts`) ersetzt `formatDateTimeRange` in der Events-Liste (reiner Datumsbereich statt Datum+Uhrzeit).
